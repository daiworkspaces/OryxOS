# OryxOS 是什么？

**OryxOS 是面向企业私有部署的 Agent Harness OS。** 它的北极星体验是：用一句自然语言发布任务，由底座拆解任务并组织一支 Agent 团队，多个 Agent 分工协作，最终交付一个结果。

> OryxOS 当前处于阶段一：单机运行时内核。北极星描述的是产品方向，并不表示分布式 Agent 团队协作已经完整交付。

## 一句话理解

裸模型只会生成文本。生产级 Agent 还需要 Reason → Act → Observe 推理循环、上下文组装、受控工具执行、记忆、沙箱和审计。这套围绕模型的运行机制，就是 **Agent Harness**。

企业需要的不只是让一个 Agent 跑起来。它还需要管理一群 Agent 的共享层：生命周期、接入渠道、公共服务、策略、多租户，以及未来可靠的跨节点协作。这就是 **Agent Harness OS**。

| 层次 | 管理范围 | 主要职责 |
| --- | --- | --- |
| 模型 | 一次 LLM 调用 | 理解和生成 |
| Agent runtime / Harness | 一个 Agent | 推理循环、上下文、工具、记忆、沙箱、审计 |
| Agent Harness OS | 一群 Agent | 生命周期、共享能力、治理、通信和扩展 |

OryxOS 建设的是第三层，并从可靠的单节点运行时内核开始落地。

## 为什么需要它

企业 Agent 从演示走向生产，通常会遇到四道门槛：

1. **定义 Agent 要写代码**：最懂业务的人无法直接定义 Agent。
2. **云平台让数据离域**：隐私、合规和内部系统访问成为阻碍。
3. **执行过程是黑盒**：没有隔离、白名单、审计和人工审批边界，企业不敢让 Agent 执行真实动作。
4. **运行一个容易，运行一群困难**：缺少管理生命周期、共享能力和协作关系的统一操作系统层。

OryxOS 用 Markdown 定义、私有部署、策略控制的执行链路，以及面向一群 Agent 的运行底座来解决这些问题。

## 一个目录 = 一个 Agent

目标中的 Agent 定义是一个目录，而不是另一套业务应用：

```text
.oryxos/agents/production-sentinel/
├── AGENT.md        # 身份、Provider、工具和任务指令
├── MEMORY.md       # 该 Agent 的长期记忆
├── skills/         # 绑定可复用 Skill
└── scripts/        # 可选的确定性操作脚本
```

这就是“配置即 Agent”的方向：目录声明意图和能力需求，OryxOS 提供运行环境与控制边界。

## 北极星公式

```text
自然语言 (md) + Memory + Tool + MCP (Connector)
              + Skill + 知识库 + Notify = 一个 Agent
```

这条公式是产品罗盘，其中的能力会按照下方路线图逐步达到生产可用。

## 五大核心能力

### 对接 LLM

Provider 抽象使 Agent 不绑定具体模型厂商。显式的 Provider 名称映射支持多个云端或本地推理服务并存，并避免隐式路由。

### ReAct 循环

OryxOS 直接实现决策循环，不把核心行为交给外部 Agent 框架。模型判断是否及如何调用工具；OryxOS 校验并执行动作、回填观察结果，直到生成最终响应或达到迭代上限。

### 记忆

会话记忆与长期记忆使 Agent 能跨对话保留状态。长期记忆先采用文件与关键词检索，同时保留升级向量检索的接口。

### 工具体系

基础工具方向覆盖文件、Shell 和 HTTP。扩展分三档：配置 Agent 目录并复用 MCP Server、用任意语言编写自定义 MCP Server、使用原生 Java 实现深度集成。

### 对外服务

通过 REST API 暴露运行能力，让任何开发语言和业务系统都能使用 HTTP 接入。

## 路线图

### 阶段一：单机运行时内核（当前）

仓库当前已经具备 Java 21、Maven 九模块、可执行 Boot 与 CLI 应用，以及最小健康接口的工程骨架。本阶段将完成五大核心能力、配置即 Agent、单实例多 Agent、REST API 与 MCP 接入，并把单节点运行做到可靠可用。

### 阶段二：底座分布式（规划）

运行节点无状态化，持久状态外置，通过多副本支撑更大规模和高可用。

### 阶段三：跨节点 Agent 协作（愿景）

引入通信底座并对接 A2A，实现跨节点发现、委托和可靠异步协作，最终到达“一句话发布任务，由一支 Agent 团队协作交付”的北极星体验。

多租户、SSO、完整审计、工具策略、可观测和 Web 管理会伴随三个阶段逐步成熟。

## 设计原则

- 底座优先于某个特定 Agent。
- 自实现决策核心，成熟协议管道直接复用。
- 配置即 Agent。
- 对接开放标准：工具用 MCP，协作用 A2A，技能采用开放格式。
- 随系统演进保持运行实例无状态、持久状态外置。
- 把最小权限、沙箱、凭证安全和审计作为架构地基。
- 用真实单节点使用需求推动分布式复杂度。
